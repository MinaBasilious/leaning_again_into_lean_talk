“Checked in Lean” means

  • No sorry
  • Only the standard axioms
  • The kernel accepted it
  • Anyone can rerun the check

Would you referee this?

def dist (a b : Nat) : Nat := a - b

theorem tri (a b c : Nat) :
    dist a c ≤ dist a b + dist b c
On Nat, subtraction stops at zero: 1 − 2 = 0.

Lean accepts it

def dist (a b : Nat) : Nat := a - b

theorem tri (a b c : Nat) :
    dist a c ≤ dist a b + dist b c := by
  unfold dist
  omega
#eval dist 1 2   -- 0
#eval dist 2 1   -- 1
The proof is correct. The theorem is about the wrong object.

Spot the bug

def FermatsLastTheorem : Prop :=
  ∀ a b c n : ℕ, n ≥ 3 → a^n + b^n ≠ c^n
It compiles. But ℕ contains 0:
a = b = c = 0 and n = 3 is a counterexample.
Example from K. Buzzard, Xena blog, 12 Nov 2026.
Lean checks that the proof proves the statement as written.
Only a reader can check it is the one we meant.

The checker is a program

  • The theory itself could be flawed
  • Or the program could have a bug
Both have happened somewhere. In Lean, the bug came first.

Collatz, July 2026

  • A Lean “disproof” of the Collatz conjecture
  • The official kernel and Nanoda both accepted it
  • Cause: a bug with nested inductive types (issue #14576)
  • Fixed within hours
Lean kernel soundness bug #14576, postmortem by L. de Moura.

The response: more kernels

  • nanoda: an independent implementation
  • lean4lean: a reimplementation in Lean, verification in progress
  • con-leche: written in Lean, proven sound against a model
  • con-ron: a Rust port, proven to refine con-leche
L. de Moura, “Lean Now Ships with Verified Kernels”, 15 Oct 2026. Rerun with lake check --paranoid (confirm in the docs).

The idea behind “proven sound”

  • Give every type a meaning as a set
  • A function type means the set of functions
  • False means the empty set
If the kernel only accepts what has such a meaning,
no closed proof of False can exist.

After K. Buzzard, Xena blog, 12 Nov 2026.
Three questions have a command.
One needs a reader.

A type is a label, not a claim

  • “x ∈ A” is a claim you can prove or disprove
  • “x : A” says what sort of thing x is
  • Like units: 3 metres plus 5 seconds is not false, it is meaningless
  • In Lean, the type of a proof is the statement

Reading types

#eval (3 : Nat) - 5   -- 0
#eval (3 : Int) - 5   -- -2
#check and_dup        -- prints the statement
Same symbols, different types, different meaning.
